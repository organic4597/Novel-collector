# 대시보드 사용법

## 대시보드 상세 로그

상세 로그에는 대시보드 API의 GET/POST 완료·오류·소요 시간, 화면 이동·버튼 조작, 브라우저 console/JavaScript/리소스/네트워크 오류, 업데이트 단계·명령 출력·종료 코드와 프로그램 시작/종료를 기록합니다. 로그인 후 접근하며 쿠키·인증값·입력란 내용·원문·개인 경로는 로그 대상에서 제외/마스킹합니다.

수집 진행·회차 실패·목차·CAPTCHA 작업 이벤트는 이 화면에서 제외합니다. 기존 파일에 남은 작업 이벤트도 상세 로그 조회에 노출하지 않습니다. 로그 화면의 자체 polling과 로그 전송 요청은 반복 기록하지 않습니다.

같은 성공 API 요청·기본 화면/조작 로그는 하나의 그룹과 발생 횟수로 보관합니다. 처리 시간 차이는 그룹을 나누지 않습니다. 기본 표시는 한 줄 요약이며 펼치면 전체 메시지·상세 값·최초/최근 발생 시각을 확인할 수 있습니다. 경고/오류와 업데이트 단계는 일반 성공 polling에 합치지 않습니다. 반복 polling 때문에 중요한 오류가 메모리에서 밀려나지 않도록 로그 파일도 그룹 보존본으로 압축합니다.

업데이트 worker 로그는 `.updates/dashboard-events.jsonl`에 별도 보존되며 서버가 살아 있을 때 상세 로그로 합칩니다. 업데이트로 localhost가 잠시 꺼져도 원인/단계 기록은 유지됩니다. 새 서버 시작 실패는 START_SERVER, 교체 후 환경 실패는 CHECK_INSTALLED_RUNTIME 단계로 구분합니다.

## 프로그램 업데이트

하루 한 번 지정 GitHub 저장소의 최신 정식 버전을 확인합니다. 현재보다 새 버전이 있으면 상단에 알림이 나타납니다. **설정 → 프로그램 업데이트**에서 현재/최신 버전·저장소·마지막 확인을 보고 **업데이트**를 누르면 다운로드·사전 준비·로컬 백업·정상 종료·교체·재시작이 진행됩니다.

UI가 표시한 버전만 설치하며 기존 보관 DB·사이트 계정·브라우저 프로필을 새 설치 정보로 덮어쓰지 않습니다. 준비 실패는 기존 프로그램을 유지하고 교체 실패는 보존본으로 복구합니다. 재시작 중 잠깐 연결이 끊길 수 있으며 완료 후 화면을 다시 불러옵니다. 설치 폴더 쓰기 권한과 systemd worker 설정이 필요합니다. 자세한 규약은 [업데이트 문서](UPDATE.md)를 참조하세요.

## 수집 예약

작품 주소와 회차 범위를 등록합니다. 같은 작품의 동시 실행은 차단되며, 최대 두 슬롯이 작품별 회차를 순서대로 처리합니다. 전체 일시정지는 인증 성공 뒤에도 유지됩니다.

각 예약 카드의 **예약 삭제**로 대기·수집 중·일시정지·확인 필요·실패 항목을 목록에서 제거할 수 있습니다. 수집 중이면 먼저 종료를 요청하고, 종료가 오래 걸릴 때는 삭제 중 상태로 처리한 뒤 완료합니다. 이미 저장한 본문과 보관함은 유지하며, 예약 기록은 로컬 trash로 옮깁니다. 다른 슬롯의 수집은 취소하지 않습니다.

본문이 없거나 준비되지 않은 회차는 실패 목록에 기록하고 다음 회차로 넘어갑니다. 일반 실패가 여러 번 이어져도 전체 수집을 멈추지 않습니다. **HTTP 429·Retry-After처럼 서버가 요청 제한을 명시했을 때만 요청 대기**를 적용합니다. CAPTCHA 자동 5회 실패의 수동 폴백은 이 요청 제한과 다른 상태입니다.

진행 카드에는 저장/전체/기존 회차/실패 수와 남은 시간이 표시됩니다. CAPTCHA가 발생하면 자동 시도 횟수와 단계를 보여주고, 각 재시도에서 처리 지연을 반영해 예상 시간을 다시 계산합니다. 표본이 없으면 숫자를 만들어 내지 않고 계산 중으로 표시합니다.

## CAPTCHA

- 수동 화면이 로딩 중이면 입력·적용을 비활성화하고 화면 준비 상태를 표시합니다. 화면 이미지가 표시된 뒤 직접 인증할 수 있습니다.
- 자동 처리 중에는 수동 화면 조회를 중단합니다. 취소한 요청의 늦은 완료로 조회를 다시 시작하지 않으며, 다른 탭의 처리로 409가 반환되면 상태를 확인해 충돌 안내 대신 진행 상태를 표시합니다.
- 인증 브라우저 열기 실패는 원인 코드와 단계로 구분합니다. 종료된 세션은 한 번 정리해 다시 열고, 실행 파일 누락·권한·프로필 사용·DNS·HTTPS·대기 시간 실패는 상세 로그로 확인합니다.

- 요구가 없으면 모듈은 실행되지 않습니다.
- 자동 시도는 최대 **5회**입니다. 남은 자동 시도가 있을 때 수동 화면은 열지 않습니다.
- 모두 실패하면 **CAPTCHA 풀기**로 수동 화면을 사용할 수 있습니다.
- **자동 CAPTCHA 재시도**는 동일 서버 세션에서 새로운 5회 예산으로 다시 확인합니다. 진행 중 중복 실행과 수동 입력은 차단됩니다.
- 창에는 `자동 CAPTCHA 2/5 · ANALYZING`처럼 진행을 표시합니다. 자동 입력 중에는 프레임·수동 입력 요청을 멈춥니다.
- 성공하면 실제 본문을 확인·저장하고 필요한 나머지 슬롯을 확인합니다. 모든 필수 슬롯이 확인되면 수집을 재개합니다.
- 창 닫기·로그아웃은 자동 재시도를 취소합니다. 서버 요청 제한이나 세션 변경은 횟수보다 우선합니다.

## 상세 로그

**상세 로그** 메뉴에서 대시보드 API·화면 조작·브라우저 열기 실패·업데이트·서비스 시작과 종료를 확인합니다. 수집 진행과 접근 재확인의 상태 알림은 이 화면에서 제외합니다. 수준/동작 필터, 표시된 로그 검색, 실시간 갱신 정지, 이전 로그 조회를 제공합니다.

- 한 페이지 최대 200개, 화면은 최대 500개 항목을 유지합니다.
- 조회는 페이지가 보일 때만 수행하고 새 항목은 cursor로 받습니다.
- 서버는 최근 5,000개를 메모리에 유지하고 2MiB 크기의 로컬 파일을 순환 보관합니다.
- API 경로·응답 상태·처리 시간·화면 구성 요소·업데이트 단계·명령 종료 코드와 브라우저 오류 코드를 진단합니다. 쿠키·토큰·proof·비밀번호·본문 원문은 기록하지 않습니다.
- 예전 로그는 새 로그 저장소로 자동 가져오지 않습니다. 작품별 기존 로그는 오른쪽 로그 패널에서 확인할 수 있습니다.

## 보관함과 성능

보관함에서 TXT/EPUB와 ZIP을 다운로드하고 실패 회차를 재수집할 수 있습니다. 인증 대기여도 저장 자료는 사용할 수 있습니다.

대시보드는 변경 카드만 교체하고, 화면 밖 카드의 렌더링을 지연합니다. 숨긴 탭은 조회를 중지하며 CAPTCHA 창이 열렸을 때 일반 상태 조회와 보관함 갱신 빈도를 낮춥니다. 전체 자료를 반복 조회하는 방식 대신 제한된 로그·페이지를 사용합니다.

## 작품 찾기와 소개 팝업

목록은 **페이지당 40개**로 구성합니다. 원본 사이트가 더 많이 표시해도 초과 작품은 다음 대시보드 페이지로 이어집니다. 마지막 페이지와 회차 필터 적용 결과는 40개보다 적을 수 있습니다. 페이지 이동 뒤 첫 번째 작품 위치로 자동 스크롤하며 검색 조건과 체크한 작품을 유지합니다.

작품 카드 또는 제목을 누르면 현재 목록 위에 작품 소개 팝업이 열립니다. 표지·작가·공급처·장르·태그·줄거리·연재 상태·확인된 회차 수를 표시합니다. 사이트가 제공하지 않은 정보는 미확인 또는 정보 없음으로 표시합니다.

팝업에서 **이 작품 수집 예약**, **선택에 담기**, **원본 소개 페이지**를 사용할 수 있습니다. ×·닫기·Esc로 닫으며 현재 목록 위치·검색 조건·선택은 그대로 유지합니다. 닫은 뒤 키보드 초점은 작품 카드로 돌아옵니다. 제목 링크는 키보드와 새 탭으로 열기에도 사용할 수 있습니다.

소개 조회는 일반 작품 페이지 한 번만 읽으며 회차 전체 스캔이나 본문 수집을 시작하지 않습니다. 저장된 소개는 30분간 재사용하고 같은 작품의 동시 요청은 하나로 합칩니다. 조회 중 화면 이동·숨김·로그아웃은 화면 반영과 추가 폴링을 중지합니다. 목록 갱신의 빈 작가/태그가 저장 소개를 지우지 않습니다.

팝업이 열려 있을 때 뒤쪽 목록의 자동 회차 확인은 보류합니다. 닫으면 기존 목록에서 확인을 재개합니다.

## 추출 프리셋

**프리셋 → 세 페이지 유형 → 추출 항목** 구조입니다. 소설 목록(`/novel`), 소설 정보·회차 목록(`/novel/{workId}`), 회차 본문(`/novel/{workId}/{episodeId}`)을 하나의 프리셋에 저장합니다. 정보 페이지의 소설 제목과 아래 회차 제목은 별도 항목입니다.

이미지 안내를 확인하고 북마크를 등록한 뒤 **원본 새 탭 열기**로 이동합니다. 원본 도구에서 항목 → 영역 클릭 → **이 항목 저장**으로 고정합니다. 같은 항목을 다시 고르면 고정 영역이 강조되고, **선택 항목 미리보기**는 해당 값만 보여줍니다. 모두 지정한 뒤 **프리셋 서버 저장**을 누르면 대시보드에서 검증·저장합니다. 로그인/저장 연결이 만료되면 새 북마크를 등록하거나 고급 JSON 가져오기를 사용합니다. 북마크바 표시는 Ctrl+Shift+B (Mac: ⌘+Shift+B)입니다.

원본 화면과 조작은 개인 브라우저에서 처리하며 서버 캡처를 사용하지 않습니다. 같은 브라우저 프로필의 기존 로그인 상태·북마크를 사용합니다. 웹앱이 북마크를 자동 등록하거나 새 창에서 자동 실행할 수는 없습니다. 새 창/탭 형태는 브라우저 설정에 따라 달라집니다. 현재 기능은 프리셋 제작·검증·관리 단계이고 자동 수집 파서의 활성화 연결은 후속 단계입니다. [상세 사용법](PRESETS.md)을 참조하세요.
