# 대시보드 사용법

## 수집 예약

작품 주소와 회차 범위를 등록합니다. 같은 작품의 동시 실행은 차단되며, 최대 두 슬롯이 작품별 회차를 순서대로 처리합니다. 전체 일시정지는 인증 성공 뒤에도 유지됩니다.

각 예약 카드의 **예약 삭제**로 대기·수집 중·일시정지·확인 필요·실패 항목을 목록에서 제거할 수 있습니다. 수집 중이면 먼저 종료를 요청하고, 종료가 오래 걸릴 때는 삭제 중 상태로 처리한 뒤 완료합니다. 이미 저장한 본문과 보관함은 유지하며, 예약 기록은 로컬 trash로 옮깁니다. 다른 슬롯의 수집은 취소하지 않습니다.

본문이 없거나 준비되지 않은 회차는 실패 목록에 기록하고 다음 회차로 넘어갑니다. 일반 실패가 여러 번 이어져도 전체 수집을 멈추지 않습니다. **HTTP 429·Retry-After처럼 서버가 요청 제한을 명시했을 때만 요청 대기**를 적용합니다. CAPTCHA 자동 5회 실패의 수동 폴백은 이 요청 제한과 다른 상태입니다.

진행 카드에는 저장/전체/기존 회차/실패 수와 남은 시간이 표시됩니다. CAPTCHA가 발생하면 자동 시도 횟수와 단계를 보여주고, 각 재시도에서 처리 지연을 반영해 예상 시간을 다시 계산합니다. 표본이 없으면 숫자를 만들어 내지 않고 계산 중으로 표시합니다.

## CAPTCHA

- 요구가 없으면 모듈은 실행되지 않습니다.
- 자동 시도는 최대 **5회**입니다. 남은 자동 시도가 있을 때 수동 화면은 열지 않습니다.
- 모두 실패하면 **CAPTCHA 풀기**로 수동 화면을 사용할 수 있습니다.
- **자동 CAPTCHA 재시도**는 동일 서버 세션에서 새로운 5회 예산으로 다시 확인합니다. 진행 중 중복 실행과 수동 입력은 차단됩니다.
- 창에는 `자동 CAPTCHA 2/5 · ANALYZING`처럼 진행을 표시합니다. 자동 입력 중에는 프레임·수동 입력 요청을 멈춥니다.
- 성공하면 실제 본문을 확인·저장하고 필요한 나머지 슬롯을 확인합니다. 모든 필수 슬롯이 확인되면 수집을 재개합니다.
- 창 닫기·로그아웃은 자동 재시도를 취소합니다. 서버 요청 제한이나 세션 변경은 횟수보다 우선합니다.

## 상세 로그

**상세 로그** 메뉴에서 수집·목차·CAPTCHA·대시보드 변경 요청·서비스 시작과 종료를 확인합니다. 수준/동작 필터, 표시된 로그 검색, 실시간 갱신 정지, 이전 로그 조회를 제공합니다.

- 한 페이지 최대 200개, 화면은 최대 500개 항목을 유지합니다.
- 조회는 페이지가 보일 때만 수행하고 새 항목은 cursor로 받습니다.
- 서버는 최근 5,000개를 메모리에 유지하고 2MiB 크기의 로컬 파일을 순환 보관합니다.
- 단계, 처리 시간, 시도 횟수, 좌표, 오류 코드와 작업 식별자만 진단합니다. 쿠키·토큰·proof·비밀번호·본문 원문은 기록하지 않습니다.
- 예전 로그는 새 로그 저장소로 자동 가져오지 않습니다. 작품별 기존 로그는 오른쪽 로그 패널에서 확인할 수 있습니다.

## 보관함과 성능

보관함에서 TXT/EPUB와 ZIP을 다운로드하고 실패 회차를 재수집할 수 있습니다. 인증 대기여도 저장 자료는 사용할 수 있습니다.

대시보드는 변경 카드만 교체하고, 화면 밖 카드의 렌더링을 지연합니다. 숨긴 탭은 조회를 중지하며 CAPTCHA 창이 열렸을 때 일반 상태 조회와 보관함 갱신 빈도를 낮춥니다. 전체 자료를 반복 조회하는 방식 대신 제한된 로그·페이지를 사용합니다.
