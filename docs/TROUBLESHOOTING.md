# 설치·로그인·수집 문제 해결

[README](../README.md) · [설치 안내](INSTALL.md) · [이용 매뉴얼](DASHBOARD.md)

## 설치가 끝나지 않거나 실행되지 않음

| 보이는 상황                             | 확인할 내용                                                                       |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| `run.mjs` 또는 `package-lock.json` 없음 | 압축 안쪽의 실제 설치 폴더에서 실행하는지 확인                                    |
| PowerShell 스크립트 실행 거부           | 설치 안내의 `-ExecutionPolicy Bypass -File` 명령을 해당 스크립트에 사용           |
| `node` 명령을 찾지 못함                 | 포터블 설치는 `start.ps1`/`start.sh`가 PATH를 구성하므로 시작 스크립트로 실행     |
| `먼저 install.sh` 안내                  | 첫 설치를 완료한 뒤 시작 스크립트 실행                                            |
| root 설치에서 실행 계정 요구            | 계정을 먼저 만들고 `--service-user`로 지정                                        |
| sudo/OS 패키지 설치 실패                | 서버 관리 권한과 인터넷·배포판 패키지 저장소를 확인하고 설치 스크립트를 정상 완료 |
| Node/uv/Python/Chromium 다운로드 실패   | 표시된 다운로드 단계, 네트워크·디스크 여유·실행 계정 쓰기 권한 확인               |

root로 브라우저를 실행하거나 sandbox를 끄는 방식으로 설치 오류를 해결하지 않습니다. [서비스 계정 설치](INSTALL.md#rockylinux-서버-설치)를 따릅니다.

설치가 완료된 폴더에서 환경 점검만 실행할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 --check
```

```sh
bash start.sh --check
```

Linux 서비스 설치에서는 같은 점검을 실제 실행 계정으로 합니다. `--check`는 설치하지 않으므로 빠진 런타임은 첫 설치 과정에서 준비해야 합니다.

## 대시보드 주소가 열리지 않음

1. 프로그램 실행 창의 주소 또는 서비스의 `active (running)`을 확인합니다.
2. 같은 PC는 `127.0.0.1`, 다른 PC는 **서버의 실제 IP/호스트**와 수신 포트를 사용합니다.
3. 기본 `HOST=127.0.0.1`은 다른 기기의 직접 접속을 받지 않습니다. [LAN/HTTPS 설정](INSTALL.md#다른-pc와-모바일에서-접속)을 확인합니다.
4. `0.0.0.0`은 수신 설정값이며 브라우저 주소가 아닙니다.
5. 포트 변경, 방화벽, 프록시/터널의 서비스 URL이 실제 수신 주소와 맞는지 확인합니다.

`EADDRINUSE`이면 다른 프로세스 또는 다른 설치가 같은 포트를 사용합니다. 무관한 Node 프로세스를 일괄 종료하지 말고 기존 설치와 포트를 확인합니다. 같은 설치의 시작 스크립트는 기존 인스턴스를 정상 교체하지만 다른 설치를 강제 종료하지 않습니다.

서비스 예시의 상태와 로그:

```sh
sudo systemctl status novel-collector.service --no-pager
sudo journalctl -u novel-collector.service -n 50 --no-pager
```

실제 서비스 이름이 다르면 바꿉니다.

## 초기 관리자 로그인 또는 비밀번호 분실

- 초기 비밀번호는 **설치한 서버**의 `secrets/admin-login.txt`입니다. 설치만 했고 서버를 처음 실행하지 않았다면 아직 없을 수 있습니다.
- 원본 사이트 비밀번호나 PIN은 관리자 로그인에 사용하지 않습니다.
- 관리자 비밀번호를 변경했다면 초기 파일은 삭제됩니다. 변경한 비밀번호로 로그인합니다.
- 로그인 쿠키가 만료되면 다시 로그인합니다. 무한히 비밀번호를 반복 입력하는 대신 파일·변경 여부를 확인합니다.
- [직접 로컬 웹 복구/서버 수동 복구](INSTALL.md#관리자-비밀번호를-잊었을-때)를 사용합니다. 공개 도메인과 LAN 주소의 웹 초기화는 허용되지 않습니다.

복구는 관리자 인증을 변경하는 절차이며 작품 DB·설정·사이트 계정·브라우저 프로필을 삭제하는 절차가 아닙니다. 파일 저장에 실패했다면 안내 창에서 새 접속 정보 파일 저장을 다시 시도합니다.

## 로그인 직후 다시 로그인 화면으로 돌아옴

사용하는 주소의 HTTP/HTTPS와 쿠키 설정을 확인합니다. HTTPS 프록시용 `SECURE_COOKIES=1`을 직접 HTTP 접속에도 그대로 적용하면 로그인 쿠키를 사용할 수 없을 수 있습니다. 신뢰하는 프록시의 전달 프로토콜, 앱의 `TRUST_PROXY`, 접속 Origin을 함께 맞춥니다.

브라우저의 쿠키 차단·별도 프로필, 다른 기기에서의 관리자 비밀번호 변경, 세션 만료도 확인합니다. 초기 인증 파일이나 DB를 삭제하지 않습니다.

## 사이트 로그인과 추가 인증이 필요함

**관리 → 설정 → 사이트 계정**에서 해당 사이트를 선택하고 아이디·비밀번호·숫자 4자리 PIN을 확인합니다. 저장한 값이 있더라도 사이트 자체가 로그인 만료·추가 인증을 요구할 수 있습니다.

대시보드가 수동 인증을 안내하면 **CAPTCHA 풀기 → 서버 화면에서 사용자가 직접 완료 → 적용 및 수집 재개** 순서로 진행합니다. 개인 PC의 다른 사이트 탭에서 완료한 인증은 서버 수집 세션과 다를 수 있습니다. 화면 조작이 어렵다면 **큰 인증창**을 사용합니다.

인증 후에도 HTTP 429/Retry-After 요청 제한이 남아 있으면 해당 대기 시간을 확인합니다. 전체 시작이나 반복 새로고침으로 제한을 해제하는 방식은 사용하지 않습니다.

## 제목·표지는 보이지만 다운로드 버튼이 없음

작품을 등록하면 정보와 표지가 먼저 저장될 수 있습니다. **저장 회차가 0**이면 본문·웹툰 이미지가 아직 저장되지 않았으므로 읽기와 다운로드가 비활성화됩니다. 예약 상태와 해당 작품의 수집 로그를 확인합니다.

총 회차가 미확인인 경우 현재 저장 수만으로 완결 수집을 판단하지 않습니다. 일부 회차만 저장된 TXT/ZIP은 저장된 자료만 포함합니다.

## 본문 없음·목차 실패·회차 실패

원본의 미업로드·준비 중 본문은 실패로 기록하고 다음 회차로 진행할 수 있습니다. 저장된 다른 회차는 보존됩니다. 실패한 회차만 선택해서 재수집하세요.

목차 조회가 끝나지 않은 상태를 전체 목차 완료로 취급하지 않습니다. 누적/예상 수와 마지막 로그를 확인하고 사이트가 정상화된 뒤 이어서 진행합니다. 같은 전체 덮어쓰기를 반복하기 전에 실패/누락 목록을 확인합니다.

웹툰의 중단/부분 저장 회차는 완료 회차와 구분합니다. 이미지 목록·내용·예약 설정이 달라져 충돌이 표시되면 내용을 확인한 뒤 명시적인 재수집/덮어쓰기를 결정합니다.

## 프리셋을 저장했는데 수집 결과가 달라지지 않음

서버 저장은 수집 적용과 다릅니다. 웹툰은 **저장 → 세 페이지 원본 확인 → 수집에 적용**을 완료해야 합니다. 기존 예약은 등록 시 고정한 설정 사본을 사용하므로 새 기본 연결이 기존 작업을 바꾸지 않습니다.

현재 소설 본문 수집 경로는 내장 파서를 사용합니다. 소설 선택자 작성/저장/검증 API가 있다는 이유로 실행에 연결됐다고 판단하지 않습니다. 원본 확인기의 브라우저와 개인 브라우저의 로그인 세션 차이도 [현재 지원 범위](PRESETS.md)에서 확인하세요.

## 화면이 예전 모습이거나 느림

- 브라우저를 새로고침하고 필요하면 Ctrl+F5로 캐시를 갱신합니다. 실제 서버 버전은 **관리 → 설정 → 프로그램 업데이트**에서 확인합니다.
- 상세 로그의 실시간 갱신을 잠시 멈추고 필터를 좁힐 수 있습니다.
- 화면 갱신 간격과 촘촘한/여유로운 화면은 **관리 → 설정 → 화면**에서 조절합니다.
- 불필요한 서버 인증창은 닫고, 서버 CPU·메모리·디스크 여유와 브라우저 실행 상태를 확인합니다.

테마 선택은 브라우저별입니다. 저장소가 차단되면 현재 페이지의 전환은 가능하지만 선택 저장이 유지되지 않을 수 있습니다.

## 업데이트 실패

**관리 → 설정 → 프로그램 업데이트 → 업데이트 작업 로그**에서 현재 단계와 오류를 확인합니다. 설치/실행 계정의 소스·런타임 교체 권한, 개인 자료 백업 읽기 권한, 서비스 이름과 쓰기 허용 경로가 맞아야 합니다.

기존 설치에 새 ZIP을 통째로 덮어쓰거나 업데이트 잠금/복구 기록을 임의로 지우지 않습니다. 중단 복구는 [업데이트 문서](UPDATE.md)를 사용합니다. 관리자 비밀번호 복구와 프로그램 업데이트 복구는 서로 다른 절차입니다.

## 도움을 요청할 때

프로그램 버전, 설치 OS, 실행 방식, 마지막 오류 문구와 관련 로그의 단계·시간을 정리합니다. 비밀번호·PIN·쿠키·토큰·본문·개인 프로필과 실제 운영 주소는 공개 이슈에 첨부하지 않습니다.

작품별 진행 문제는 **수집 로그**, 프로그램 요청/업데이트 문제는 **관리 → 상세 로그**에서 필요한 부분을 확인합니다.
