# 검증 현황

검증 기준: 2026-10-03. 테스트는 임시 저장소와 합성 fixture를 사용합니다. CAPTCHA 브라우저 테스트는 격리된 로컬 서버만 호출합니다.

| 범위 | 결과 |
|---|---|
| 기존 구현 비교 실행 | 408개 중 376 통과, 32 실패 |
| 초기 CAPTCHA 확장 후 전체 | 435개 중 403 통과, 32 실패 |
| 3회 재시도·직접 연결 반영 후 전체 | 439개 중 407 통과, 32 실패 |

| 현재 이미지·오프라인 평가 Python 테스트 | 9/9 통과 |

기존 구현 비교는 새 연결 코드를 메모리 load hook에서 제거해 수행했으며 운영 파일을 덮어쓰지 않았습니다. 변경 전후 실패 테스트 이름은 동일했습니다. 따라서 전체 테스트가 모두 통과한 상태는 아닙니다.

기존 실패 분포: discovery-gate 4, discovery 4, job-profiles-http 3, job-profiles 3, library-metadata 6, site-auto-auth 2, site-browser 5, ui-site-account 1, ui-site-verification 2, viewer-origins 2. 소스 사이트 전환과 오래된 mock 계약의 불일치를 기능별로 정리해야 합니다.

새 테스트는 조건부 실행, 동시 응답 합류, 세션 변경, 챌린지 만료, 불명확한 위치, trail 시간 범위, 본문 없는 발급, 현재 쿠키, 성공 토큰 검증, 타임아웃·거부·재요구의 반복 차단, 기존 처리기의 새 nonce/proof 생성, 사람 확인 인계, 이미지 디코딩·크기·오차와 평가 지표를 확인합니다.

합성 위치 표본 8개는 모두 원래 x를 정확히 산출했습니다. 이 결과는 실제 서버의 CAPTCHA 통과율을 의미하지 않습니다. 운영 이미지 평가 및 서버 검증 성공률은 별도로 측정합니다.

후속 보완에서는 단색 빈칸의 alpha 외곽 매칭과 서브픽셀 peak 보간을 추가했습니다. 해당 변경 당시 CAPTCHA Node 테스트 **28/28**, Python 이미지·평가 테스트 **9/9**가 통과했습니다. 원래 8개 질감 표본은 0.5픽셀 이내, 새 단색 표본 3개는 2픽셀 이내 위치를 산출했으며, 중복 빈칸은 제출을 보류합니다. 실제 브라우저의 소수점 x와 소수 밀리초 timestamp 보존도 검사합니다. 시점별 전체 결과는 위 표에 구분했습니다.

이후 새 챌린지로 최대 3회 자동 시도를 추가했습니다. 두 번 위치가 불확실해도 세 번째 성공 시 본문을 읽는 경우, 세 번 서로 다른 챌린지가 거부되면 네 번째 요청 없이 기존 수동 확인으로 전환하는 경우, 서버 요청 제한은 즉시 중단하는 경우를 실제 Chromium·로컬 서버로 검증했습니다. 프록시 연결 코드는 제거했고 현재 전체 실패 32개는 기존 기준선과 동일한 항목입니다.

목차 시간 초과 보완 후에는 목차 테스트 **19/19**와 기존 수집 통합 테스트 **22/22**를 확인했습니다. 새 탐색 한 번으로 복구하는 경우와 계속 일부 목차만 보이는 경우의 구조화된 진단을 추가했습니다. 이 두 테스트는 위 전체 439개 실행 이후 추가된 항목입니다.

## 최신 전체 결과

5회 자동 예산·재시도 API·수동 UI 차단·화면 밖 슬라이더·ETA·목차 재사용·상세 로그·키 기반 카드 갱신 반영 후 **454개 중 422 통과, 기존 실패 32개**입니다. 기존 실패 항목은 초기 비교 실행과 동일합니다. CAPTCHA 집중 테스트는 **34/34**, Python 이미지 테스트는 **9/9** 통과했습니다.

추가 확인: 재시도 POST202와 입력 검증, 자동 진행 중 수동 화면/입력 차단, 닫기 시 취소, 다섯 번째 성공과 예산 소진 폴백, 동시 상태/예약 조회의 한 번의 디스크 스캔, 로그 인증·redaction·cursor·파일 순환, 숨긴 상세 로그 페이지의 조회 중단, 목차 재사용, 한 카드 변경 시 나머지 19개 카드와 키보드 초점 보존입니다.

실제 원본 서버에서도 자동 검증 성공 2건과 이후 본문 저장 재개를 확인했습니다. 이 관찰은 모든 챌린지의 성공률을 보장하지 않습니다.

## 예약 삭제·본문 실패 건너뛰기 반영

추가 변경 후 전체 결과는 **463개 중 431 통과, 기존 실패 32개**입니다. 예약 삭제 테스트 5개와 UI 삭제, HTTP404 안내, 오래된 연속 실패 대기 해제, 명시적 서버 제한 보존을 검증했습니다. 실제 수집 통합 fixture에서는 본문 없는 회차 7개를 실패 기록 후 건너뛰고 8번째 정상 회차를 저장하며 전체 요청 대기를 시작하지 않는 것을 확인했습니다.

진행 중 삭제는 worker 종료를 scheduler control lock 밖에서 기다립니다. 늦은 종료는 DELETE202로 안내하며 중복 삭제·재개·늦은 PC worker 쓰기를 방지합니다. 저장 본문과 다른 수집 슬롯은 보존합니다. 이 검증에 기존 실패 32개를 통과한 것으로 표시하지는 않습니다.

## 작품 소개 화면

카드 클릭 소개 화면 추가 후 전체 결과는 **469개 중 437 통과, 기존 실패 32개**입니다. 소개 전용 조회는 한 작품 페이지를 한 번 읽고 회차 목차 스캔을 하지 않는지, 같은 작품 동시 요청과 30분 캐시, 빈 목록 메타데이터로 저장 작가·태그·줄거리를 지우지 않는지 검증했습니다.

UI 검증은 소개 정보의 안전한 텍스트 표시, 외부 표지 직접 삽입 차단, 캐시 재개방, 수집 예약·선택에 담기, 늦은 응답/로그아웃 처리, 목록 복귀 시 검색 조건과 체크박스 유지입니다. 실제 Chromium의 데스크톱/모바일 소개 화면과 뒤로가기도 확인했으며 JavaScript 오류와 가로 넘침은 없었습니다. 공개 작품 소개 페이지에서는 작가·태그·줄거리 추출 가능 여부를 확인했고 원문을 공개 fixture에 저장하지 않았습니다.

```sh
npm test
npm run test:captcha
npm run test:captcha:images
```

Python 테스트 전 `requirements-captcha.txt`의 의존성을 `.venv-captcha`에 설치하세요. 브라우저 테스트는 `BROWSER_PATH`로 지정한 Chromium 또는 로컬 설치 경로의 Chromium을 사용합니다.
