# 문제 해결

## 목차 불러오기 실패

본문 저장 완료 로그 뒤 목차 오류가 있으면 서비스 재시작·작업 재개 시점도 확인합니다. 저장된 본문은 별도로 보존됩니다. 목차 시간 초과는 새 탐색 한 번으로 다시 확인하고, 계속 실패하면 누적/예상 개수와 더 보기 버튼 상태를 기록합니다. 부분 목차를 전체로 취급하지 않습니다.

`누적 100/300, 이전 0, 더 보기 대기`는 목록·버튼 준비가 끝나지 않은 상태입니다. HTTP429와 Retry-After는 정상 대기이며 새로고침으로 건너뛰지 않습니다.

## CAPTCHA가 수동 대기로 전환됨

상세 로그의 마지막 시도와 오류를 확인합니다. 자동 5회 실패 후에는 정상 폴백입니다. **자동 CAPTCHA 재시도** 또는 기존 수동 창을 사용할 수 있습니다.

- `POSITION_UNCERTAIN`: 점수 임계값 미설정 또는 후보 불명확
- `ANALYZER_UNAVAILABLE`: Python/OpenCV 환경·실행 권한 확인
- `IMAGE_SIZE_MISMATCH`: 현재 응답 이미지 규격 확인
- `CAPTCHA_INPUT_BLOCKED`: 다른 요소가 슬라이더를 가리는지 확인
- `VERIFY_REJECTED`: 서버가 답안을 거부함
- `VERIFY_RESULT_UNKNOWN`: 응답 확정 불가. 늦은 토큰을 사용하지 않고 다음 시도는 새 챌린지 사용
- `REQUEST_BLOCKED`: 실제 서버 제한·네트워크 보호가 우선됨

슬라이더가 화면 밖에 있으면 자동 입력 전에 일반 스크롤로 화면 안에 가져옵니다. 입력 좌표와 실제 hit target이 맞아야 제출합니다. `trail.x`·`trail.t` 소수점은 유지하고 최종 `x`만 원본 규약대로 반올림합니다.

## 대시보드가 느림

상세 로그의 실시간 갱신을 잠시 멈추고 필터를 좁혀 보세요. 다른 탭을 숨기거나 불필요한 CAPTCHA 창을 닫으면 프레임 조회가 중지됩니다. 설정의 상태 갱신 간격을 늘릴 수도 있습니다.

현재 변경 카드만 렌더링, 조회 중복 억제, 로그 cursor, 화면 밖 렌더링 지연, 목차 재사용이 적용돼 있습니다. 응답이 계속 느리면 서비스의 CPU/메모리·디스크 여유·Chromium 프로세스를 확인합니다.

## Chromium 또는 Python 실행 실패

서비스 사용자에게 실행 파일·프로필·cache 읽기/쓰기 권한이 있는지 확인합니다. `BROWSER_PATH`는 디렉터리가 아니라 실행 파일입니다. Playwright 설치 브라우저는 설치한 사용자의 cache에 저장됩니다.

```sh
.venv-captcha/bin/python -c "import cv2, numpy; print(cv2.__version__, numpy.__version__)"
npm run test:captcha
```

Sandbox를 끄기보다 운영체제의 브라우저 의존성과 사용자 권한을 먼저 확인합니다.

## 문서·설정 공유

오류 코드와 처리 시간은 공유할 수 있지만 수집 본문, 계정, 쿠키, 토큰, proof, 실제 운영 주소와 프로필은 공개 이슈에 첨부하지 않습니다. Git 공개 전에는 `node tools/check-publication.mjs`로 추적 파일을 확인하세요.
