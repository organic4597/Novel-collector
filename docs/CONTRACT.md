# 기능 계약

## 저장과 작업

- 최대 두 작업, 작품 내부 회차는 순차 처리합니다. 같은 작품의 동시 실행을 막습니다.
- Scheduler가 작업 상태와 일시정지·취소·재개를 소유합니다. 사용자 일시정지는 자동 인증 복구나 대기 만료보다 우선합니다.
- FolderStore가 본문, 작은 회차 메타데이터, 실패 기록과 내보내기를 원자적으로 저장합니다. 작업 기록 삭제와 보관 본문 삭제는 구분합니다.
- 캐시한 정상 회차는 재사용하며 실제 본문 요청만 요청 실패·대기 통계에 반영합니다.
- 목차 로딩 시간 초과는 새 탐색으로 한 번 더 확인합니다. 다시 실패하면 누적/예상 회차 수와 더 보기 버튼 상태를 기록하며, 일부 목차를 전체로 저장하지 않습니다. 인증·요청 제한·취소는 이 재시도 대상이 아닙니다.

## 브라우저와 인증

- 슬롯별 Context/Page를 배타적으로 소유합니다. 사람 확인이 끝나면 같은 브라우저를 수집기에 인계합니다.
- 정상 본문 확인과 저장 checkpoint가 끝나야 해당 슬롯의 인증 대기를 해제합니다.
- 자동 로그인은 현재 세션의 정상 로그인/PIN 요청만 사용합니다. 계정은 사이트별로 암호화하며 다른 origin으로 복사하지 않습니다.
- 공개 API와 로그에 비밀번호, PIN, 쿠키, CAPTCHA 토큰, proof 원문을 노출하지 않습니다.

## 조건부 CAPTCHA

- 현재 회차 응답의 `error === 'captcha_required_daily_quota'`가 실행 기준입니다. 일반 응답은 분석이나 입력을 시작하지 않습니다.
- 세션별 한 번의 진행 작업을 공유하고 호출자별 요청 ID를 보존합니다.
- 원본 뷰어의 본문 없는 발급 요청을 채택합니다. 챌린지 ID·이미지·크기·y·수신 시각을 한 객체로 취급합니다.
- 명확한 후보에 대해서만 실제 브라우저 입력을 수행합니다. trail 시간 범위는 1800..4500ms, 기본 목표는 2400ms입니다.
- 같은 챌린지는 한 번만 검증합니다. 재시도 가능한 실패는 현재 회차의 새 요청과 새 챌린지로 최대 5회 시도하고, 다섯 번째 실패에서 기존 수동 CAPTCHA 확인으로 전환합니다. 자동 예산이 남아 있으면 수동 UI를 표시하지 않습니다. 작업 취소·세션 변경·요청 제한은 즉시 중단합니다.
- 엄격한 성공 응답을 기존 처리기에 전달하고, 콘텐츠 요청의 nonce/proof 갱신은 기존 처리기가 맡습니다. 타임아웃 뒤 늦은 토큰은 전달하지 않으며 이전 답안이나 proof를 재전송하지 않습니다.
- 자동 재시도 버튼은 같은 소유 세션에서 새 5회 예산을 시작합니다. 진행 중 중복 실행과 수동 입력을 차단하며, 성공 시 실제 본문을 저장한 뒤 필수 슬롯을 확인해 재개합니다.
- 단계별 ETA는 현재 확인 시간을 반영합니다. 인증 재시도는 목차를 다시 읽지 않으며, 재개 시 완전성이 검증된 저장 목차를 재사용합니다.
- 상세 로그는 관리자 인증·bounded cursor·메모리 상한·로컬 파일 순환을 사용합니다. 인증값·본문·원시 응답을 저장하지 않습니다.

상세 인터페이스, 오류 코드와 평가 방법은 [CAPTCHA 문서](CAPTCHA.md)를 참조하세요.
