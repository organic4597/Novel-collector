# 대시보드 사용법

## 서점형 디자인과 라이트·다크 모드

기존 세로 사이드바와 관리 카드 중심의 시각 구조를 교체했습니다. 작품 찾기와 보관함을 서점의 진열처럼 탐색하고, 예약·설정은 같은 서비스 안의 관리 화면으로 사용할 수 있게 구성합니다. 이전 디자인의 색과 배치를 유지하는 방식으로 개편하지 않습니다. 기존 기능의 ID·입력 제약·API·저장 데이터·수집 동작을 연결 기준으로 보존합니다.

### 설계 방향

다차원 분석에서는 처음 로그인하는 사용자, 작품을 여러 개 고르는 사용자, 이미 저장한 작품을 읽는 사용자, 수집 문제를 관리하는 사용자의 화면을 함께 검토합니다. 같은 동작을 반복할 때 메뉴와 버튼을 찾는 비용, 휴대전화와 데스크톱에서 정보가 차지하는 공간, 밝은 환경과 어두운 환경에서 글자가 읽히는 정도를 검토 기준으로 삼습니다. 복잡성 분해에서는 메뉴·작품·선택·진행·설정·팝업의 역할을 분리하고, 각 역할이 사용할 수 있는 공통 버튼과 표면·텍스트 색을 정합니다. 수식이나 추정 점수는 실제 측정값으로 사용하지 않습니다.

기존 디자인 정리는 색과 간격을 맞췄지만 화면의 골격은 바꾸지 못했습니다. 이번 구현은 메뉴를 상단으로 이동하고 주 탐색과 관리 기능의 접근 경로를 나눕니다. 작품 목록은 카드 테두리보다 표지가 먼저 보이는 진열로 바꾸고, 예약은 작품 설명과 진행 정보를 두 영역으로 배치합니다. 로그인은 이야기와 접속 입력을 분리한 두 영역 화면으로 바꿉니다. 설정은 넓은 편집 패널과 항목 탐색·저장 바를 사용하는 화면으로 바꿉니다.

라이트와 다크는 동일한 구성에 각각 읽기 좋은 표면과 글자 색을 갖습니다. 라이트의 바탕은 종이색, 표면은 흰색, 주요 동작은 짙은 녹색입니다. 다크의 바탕은 어두운 녹색 중성색, 표면은 더 밝은 서재색, 주요 동작은 밝은 연두색입니다. 오류와 경고는 각 배경에서 읽히는 색과 상태 문구를 함께 사용합니다. 단순히 CSS 이름만 바꾸지 않고 실제 브라우저의 배경 밝기와 color-scheme, 글자 명암 대비를 검사합니다.

반복 작업과 성능을 고려하여 목록 캐시와 카드·이미지 재사용은 유지합니다. 테마를 바꿀 때 API나 수집 요청을 만들지 않습니다. 외부 글꼴·새 UI 프레임워크·대형 비트맵 자료를 추가하지 않고 시스템 글꼴과 작은 SVG를 사용합니다. 로그 창은 별도 레이어로 펼쳐져 전체 목록을 다시 좁히지 않습니다. 과도한 흐림과 움직임을 사용하지 않습니다. 디자인 변화와 원본 사이트의 수집·인증 가능 여부는 각각 검증해야 합니다.

### 적용한 12가지 구성

1. **가로 메뉴.** 왼쪽 세로 메뉴를 없애고 상단에 작품 찾기·작품 보관함·수집 예약·수집 기록을 배치합니다. 설정·추출 프리셋·상세 로그·업데이트 내역은 관리 메뉴에 모읍니다. 기존 메뉴 식별자와 현재 화면 표시를 유지하며, 관리 메뉴의 네 화면도 키보드로 접근할 수 있습니다. 선택 후 메뉴를 닫고 초점을 관리 버튼으로 돌립니다. Esc와 메뉴 바깥 클릭으로도 닫을 수 있습니다.

2. **두 가지 테마.** 로그인과 상단에 라이트·다크 전환 버튼이 있습니다. 처음 사용하면 라이트로 시작하고 선택은 브라우저의 collector.theme에 저장합니다. 다른 탭의 변경도 동기화하며, 저장소가 막혀 있어도 현재 화면에서 전환할 수 있습니다. 테마는 로그인·로그아웃이나 화면 이동으로 초기화하지 않습니다. 비밀번호나 작품 데이터는 이 설정에 저장하지 않습니다.

3. **첫 화면을 위한 별도 로그인 디자인.** 큰 문장과 책 그림이 있는 소개 영역, 관리자 접속 입력 영역을 분리합니다. 휴대전화에서는 접속 폼을 한 열로 표시합니다. 초기 접속 파일 확인, 공식 다운로드와 설치 안내, 원격 수동 복구, 로컬 경고·확인 문구·새 접속 파일 저장 절차는 유지합니다. 로그인·복구 기능을 소개 문구나 장식 뒤에 숨기지 않습니다.

4. **작품 찾기 소개 영역.** 새로운 큰 제목과 가벼운 책 그림으로 탐색 화면의 시작점을 만듭니다. 그림은 추천 작품이나 실제 저장 현황으로 표시하지 않는 장식입니다. 작품 유형·검색 대상·검색어를 먼저 배치하고 나머지 검색 조건을 이어서 표시합니다. 회차 범위·미확인 포함도 같은 검색 패널에 모읍니다. 제목·작가 검색과 웹툰 연재 상태·형식 전환은 기존 동작을 사용합니다.

5. **표지 중심 진열.** 작품을 감싸는 큰 관리 카드 대신 표지, 제목, 작가, 태그와 회차 정보가 차례로 보이게 합니다. 기본 표지는 전체 보기이며 기존 틀 채우기 설정도 유지합니다. 실제 표지가 없으면 제목 기반 대체 표지가 표시됩니다. 대체 표지도 두 테마의 색을 따라갑니다. 실제 이미지는 원본 캐시와 기존 DOM 노드를 사용합니다.

6. **서재 탐색.** 작품 보관함은 ‘나의 서재’로 표시하고 소설·웹툰 유형, 작품·작가 검색, 장르, 정렬을 공통 탐색 패널에 배치합니다. 페이지 선택과 전체 선택의 차이, ZIP 다운로드의 범위, 회차 읽기와 개별 내보내기, 저장·누락 회차 정보는 그대로 유지합니다. TXT와 웹툰 이미지 읽기, CBZ와 작품 ZIP, 다운로드 준비 상태와 실패 재수집을 사용할 수 있습니다.

7. **예약의 정보 배치.** 진행 중·대기·저장 회차·수집 위치는 분리된 큰 관리 카드에서 간결한 수치 영역으로 바꿉니다. 예약 항목은 작품 정보와 진행률을 나란히 보여줍니다. 현재 회차와 예상 시간, 오류는 필요한 만큼 표시하고 조작 버튼은 아래쪽에 모읍니다. 드래그 및 키보드 순서 이동, 로그·일시정지·취소·삭제·내보내기의 상태별 조건은 유지합니다.

8. **설정 편집 패널.** 항목별 바로가기와 넓은 입력 패널, 큰 구역 제목, 저장 상태와 하단 저장 바를 사용합니다. 수집·화면 설정, 빠른 설정, 비밀번호 변경·보기, 서버 정보, 사이트 계정 관리, 설정 파일 가져오기·내보내기, 프로그램 업데이트는 각각 기존 접근 경로를 유지합니다. 서버 수치는 행과 구분선으로 정리하고 삭제 확인은 위험 영역으로 구분합니다.

9. **공통 팝업.** 작품 소개·예약·여러 주소·묶음 다운로드·실패 재수집·읽기 팝업은 같은 표면과 제목·닫기 규격을 사용합니다. 좁은 화면에서는 내용이 스크롤되며 닫기·확인·취소를 사용할 수 있습니다. 작품 소개는 넓은 표지와 정보 영역, 읽기는 회차와 본문 영역을 유지합니다. 인증창은 화면 크기와 드래그 설정을 보존하고 시각 스타일만 변경합니다.

10. **로그 사이드바.** 상단 연결 상태 옆의 수집 로그 버튼에서 오른쪽 창을 펼치고 접습니다. 목록 폭을 다시 계산하는 대신 별도 레이어를 사용하므로 작품 카드가 이동하지 않습니다. 다른 작품 선택 시 즉시 조회하고 이전 응답을 버리는 기존 동작, 로그 행과 스크롤 위치 유지도 보존합니다. 관리 메뉴의 상세 로그는 별도 진단 기능으로 계속 제공합니다.

11. **터치와 키보드.** 주요 조작의 최소 크기는 44px이고 본문 바로가기와 명확한 초점 표시를 제공합니다. 상단은 스크롤 중에도 사용할 수 있으며 페이지 이동 시 첫 작품이 상단 메뉴에 가려지지 않도록 스크롤 여백을 둡니다. 좁은 화면에서도 네 작품 메뉴, 관리·테마·로그아웃을 사용할 수 있습니다. 작은 화면에서 표나 입력 값이 가로로 밀려나지 않게 합니다.

12. **검증과 운영 적용.** 기존 화면·폼·필드·선택지·제약의 계약 검사, 테마 단위 검사, 실제 브라우저의 두 모드와 모든 화면·팝업·사용자 동작을 검사합니다. 실제 렌더링 배경과 글자 대비, 375·768·1024·1440px의 범위, 관리 메뉴와 로그 창, 키보드 전환·새로고침 유지·다른 탭 동기화를 확인합니다. 검사에는 합성 자료를 사용합니다. 개발 서버 반영과 운영 릴리스는 구분하며 운영은 검증된 릴리스와 업데이터 절차를 사용합니다.

### 구현 위치

전체 구조는 public/index.html, 새 공통 시각 규칙은 public/styles.css, 설정·계정·인증창은 기존 전용 CSS에 있습니다. public/theme.js는 스타일보다 먼저 읽어 저장한 테마를 적용하고 두 버튼을 연결합니다. public/app.js는 관리 메뉴 닫기와 초점 이동을 처리합니다. public/performance.js의 대체 표지는 공통 테마 색을 사용합니다. 서버에는 새 테마 스크립트의 정적 경로만 추가합니다. UI/UX Pro Max의 서점·편집형 탐색과 접근성 지침을 참고하며 제품 화면과 맞지 않는 대형 랜딩 페이지 추천은 적용하지 않습니다.

검증 파일은 tests/ui-redesign-contract.test.mjs, tests/ui-theme.test.mjs, tests/ui-redesign-browser.test.mjs입니다. 기존 브라우저 검사는 관리 메뉴를 거쳐 화면을 열고 고정 메뉴 아래에서 페이지 이동 결과를 확인하도록 조정합니다. 실제 사이트 수집·인증과 실기기의 장시간 스크롤 프레임률은 합성 UI 검사로 검증한 것으로 간주하지 않습니다.

## 초기 로그인과 관리자 복구

로그인 화면의 **처음 사용하거나 관리자 비밀번호를 잊었나요?** 안내에서 공식 GitHub 다운로드와 초기 접속 파일 경로를 확인합니다. 초기 비밀번호는 대시보드를 설치한 컴퓨터/서버의 `secrets/admin-login.txt`에 있습니다. 사이트 회원 계정과 별개의 관리자 비밀번호입니다.

서버의 직접 로컬 주소에서만 초기화 경고와 확인 입력이 나타납니다. 변경 범위 확인 → 정확한 확인 문구 → 재설정 → 새 접속 정보 파일 저장 → 저장 확인 → 직접 로그인 순서입니다. 공개 도메인과 프록시는 수동 복구 안내만 보여줍니다. 기존 소설·회차·예약·사이트 계정·프리셋·브라우저 프로필은 보존하며 기존 관리자 세션은 종료합니다. [초기 접속·수동 복구 절차](INSTALL.md#관리자-비밀번호를-잊었을-때)를 확인하세요.

## 대시보드 상세 로그

상세 로그에는 대시보드 API의 GET/POST 완료·오류·소요 시간, 화면 이동·버튼 조작, 브라우저 console/JavaScript/리소스/네트워크 오류, 업데이트 단계·명령 출력·종료 코드와 프로그램 시작/종료를 기록합니다. 로그인 후 접근하며 쿠키·인증값·입력란 내용·원문·개인 경로는 로그 대상에서 제외/마스킹합니다.

수집 진행·회차 실패·목차·CAPTCHA 작업 이벤트는 이 화면에서 제외합니다. 기존 파일에 남은 작업 이벤트도 상세 로그 조회에 노출하지 않습니다. 로그 화면의 자체 polling과 로그 전송 요청은 반복 기록하지 않습니다.

같은 성공 API 요청·기본 화면/조작 로그는 하나의 그룹과 발생 횟수로 보관합니다. 처리 시간 차이는 그룹을 나누지 않습니다. 기본 표시는 한 줄 요약이며 펼치면 전체 메시지·상세 값·최초/최근 발생 시각을 확인할 수 있습니다. 경고/오류와 업데이트 단계는 일반 성공 polling에 합치지 않습니다. 반복 polling 때문에 중요한 오류가 메모리에서 밀려나지 않도록 로그 파일도 그룹 보존본으로 압축합니다.

업데이트 worker 로그는 `.updates/dashboard-events.jsonl`에 별도 보존되며 서버가 살아 있을 때 상세 로그로 합칩니다. 업데이트로 localhost가 잠시 꺼져도 원인/단계 기록은 유지됩니다. 새 서버 시작 실패는 START_SERVER, 교체 후 환경 실패는 CHECK_INSTALLED_RUNTIME 단계로 구분합니다.

## 프로그램 업데이트

하루 한 번 지정 GitHub 저장소의 최신 정식 버전을 확인합니다. 현재보다 새 버전이 있으면 상단에 알림이 나타납니다. **설정 → 프로그램 업데이트**에서 현재/최신 버전·저장소·마지막 확인을 보고 **업데이트**를 누르면 다운로드·사전 준비·로컬 백업·정상 종료·교체·재시작이 진행됩니다.

UI가 표시한 버전만 설치하며 기존 보관 DB·사이트 계정·브라우저 프로필을 새 설치 정보로 덮어쓰지 않습니다. 준비 실패는 기존 프로그램을 유지하고 교체 실패는 보존본으로 복구합니다. 재시작 중 잠깐 연결이 끊길 수 있으며 완료 후 화면을 다시 불러옵니다. 설치 폴더 쓰기 권한과 systemd worker 설정이 필요합니다. 자세한 규약은 [업데이트 문서](UPDATE.md)를 참조하세요.

## 수집 예약

작품 주소와 회차 범위를 등록합니다. 같은 작품의 동시 실행은 차단되며, 최대 두 슬롯이 작품별 회차를 순서대로 처리합니다. 전체 일시정지는 인증 성공 뒤에도 유지됩니다.

수집 중·대기·일시정지 예약 카드를 드래그해 앞뒤로 이동할 수 있습니다. 모바일·키보드에서는 **순서 위로**, **순서 아래로** 버튼을 사용합니다. 수집 중인 작업은 현재 회차의 읽기·저장을 마친 뒤 변경된 순서를 확인하고, 우선순위가 밀렸으면 슬롯을 반환해 대기합니다. 다시 차례가 오면 검증된 목차와 저장한 회차를 재사용해 이어서 수집합니다. 두 슬롯 중 순서가 유지된 작업은 계속 수집합니다. 새 순서는 서버에 저장돼 재시작 뒤에도 유지됩니다. 미래 예약은 지정한 시각 이후에만 실행하며, 종료·삭제 중인 항목은 이동 대상에서 제외합니다. 저장에 실패하면 기존 순서를 유지하고 오류를 표시합니다.

각 예약 카드의 **예약 삭제**로 대기·수집 중·일시정지·확인 필요·실패 항목을 목록에서 제거할 수 있습니다. 수집 중이면 먼저 종료를 요청하고, 종료가 오래 걸릴 때는 삭제 중 상태로 처리한 뒤 완료합니다. 이미 저장한 본문과 보관함은 유지하며, 예약 기록은 로컬 trash로 옮깁니다. 다른 슬롯의 수집은 취소하지 않습니다.

본문이 없거나 준비되지 않은 회차는 실패 목록에 기록하고 다음 회차로 넘어갑니다. 일반 실패가 여러 번 이어져도 전체 수집을 멈추지 않습니다. **HTTP 429·Retry-After처럼 서버가 요청 제한을 명시했을 때만 요청 대기**를 적용합니다. CAPTCHA 자동 5회 실패의 수동 폴백은 이 요청 제한과 다른 상태입니다.

진행 카드에는 저장/전체/기존 회차/실패 수와 남은 시간이 표시됩니다. CAPTCHA가 발생하면 자동 시도 횟수와 단계를 보여주고, 각 재시도에서 처리 지연을 반영해 예상 시간을 다시 계산합니다. 표본이 없으면 숫자를 만들어 내지 않고 계산 중으로 표시합니다.

## CAPTCHA

- 수동 화면이 로딩 중이면 입력·적용을 비활성화하고 화면 준비 상태를 표시합니다. 화면 이미지가 표시된 뒤 직접 인증할 수 있습니다.
- 자동 처리 중에는 수동 화면 조회를 중단합니다. 취소한 요청의 늦은 완료로 조회를 다시 시작하지 않으며, 다른 탭의 처리로 409가 반환되면 상태를 확인해 충돌 안내 대신 진행 상태를 표시합니다.
- 인증 브라우저 열기 실패는 원인 코드와 단계로 구분합니다. 종료된 세션은 한 번 정리해 다시 열고, 실행 파일 누락·권한·프로필 사용·DNS·HTTPS·대기 시간 실패는 상세 로그로 확인합니다.

- 요구가 없으면 모듈은 실행되지 않습니다.
- 자동 시도는 최대 **5회**입니다. 남은 자동 시도가 있을 때 수동 화면은 열지 않습니다.
- 모두 실패하면 **CAPTCHA 풀기**로 수동 화면을 사용할 수 있습니다.
- **자동 CAPTCHA 재시도**는 동일 서버 세션에서 새로운 5회 예산으로 다시 확인합니다. 진행 중 중복 실행과 수동 입력은 차단됩니다.
- 창에는 `자동 CAPTCHA 2/5 · ANALYZING`처럼 진행을 표시합니다. 자동 입력 중에는 프레임·수동 입력 요청을 멈춥니다.
- 성공하면 실제 본문을 확인·저장하고 필요한 나머지 슬롯을 확인합니다. 모든 필수 슬롯이 확인되면 수집을 재개합니다.
- 창 닫기·로그아웃은 자동 재시도를 취소합니다. 서버 요청 제한이나 세션 변경은 횟수보다 우선합니다.

## 상세 로그

**상세 로그** 메뉴에서 대시보드 API·화면 조작·브라우저 열기 실패·업데이트·서비스 시작과 종료를 확인합니다. 수집 진행과 접근 재확인의 상태 알림은 이 화면에서 제외합니다. 수준/동작 필터, 표시된 로그 검색, 실시간 갱신 정지, 이전 로그 조회를 제공합니다.

- 한 페이지 최대 200개, 화면은 최대 500개 항목을 유지합니다.
- 조회는 페이지가 보일 때만 수행하고 새 항목은 cursor로 받습니다.
- 서버는 최근 5,000개를 메모리에 유지하고 2MiB 크기의 로컬 파일을 순환 보관합니다.
- API 경로·응답 상태·처리 시간·화면 구성 요소·업데이트 단계·명령 종료 코드와 브라우저 오류 코드를 진단합니다. 쿠키·토큰·proof·비밀번호·본문 원문은 기록하지 않습니다.
- 예전 로그는 새 로그 저장소로 자동 가져오지 않습니다. 작품별 기존 로그는 오른쪽 로그 패널에서 확인할 수 있습니다.

## 보관함과 성능

보관함에서 TXT/EPUB와 ZIP을 다운로드하고 실패 회차를 재수집할 수 있습니다. 인증 대기여도 저장 자료는 사용할 수 있습니다.

장르와 태그는 실제 작품 메타데이터를 비교해 같은 라벨을 한 번만 표시합니다. 앞뒤 공백과 각 목록 내부의 중복도 제거하며, 저장된 장르·태그 분류 정보는 유지합니다.

대시보드는 기존 카드·썸네일을 유지하며 변경된 문구·버튼·체크박스만 갱신하고, 화면 밖 카드의 렌더링을 지연합니다. 숨긴 탭은 조회를 중지하며 CAPTCHA 창이 열렸을 때 일반 상태 조회와 보관함 갱신 빈도를 낮춥니다. 전체 자료를 반복 조회하는 방식 대신 제한된 로그·페이지를 사용합니다.

보관함에 돌아오면 이전 목록을 즉시 표시합니다. 자동 조회는 최근 8초 안에 받은 목록을 재사용하며 수동 **새로고침**은 다시 조회합니다. 등록·삭제·설정 저장 같은 변경과 로그아웃은 관련 캐시를 무효화합니다. 이전 요청이 늦게 끝나도 변경 후 목록이나 새 로그인 세션을 덮어쓰지 않습니다.

수집 로그에서 다른 작품을 선택하면 주기 갱신을 기다리지 않고 해당 작품 로그를 즉시 조회합니다. 이전 작품의 요청을 취소하고 늦은 응답/오류를 버리며, 같은 작품의 새 로그에서는 기존 행과 사용자가 읽던 스크롤 위치를 유지합니다.

## 작품 찾기와 소개 팝업

검색 대상에서 **작품 제목** 또는 **작가 이름**을 선택한 뒤 검색어를 입력합니다. 선택한 한 가지 대상으로 원본 사이트의 공개 검색을 사용합니다. 원본 검색 결과에서 제공하지 않는 장르·플랫폼 필터나 정렬 조합은 서버 안내에 따라 해제합니다.

표지 정보가 없거나 다운로드에 실패하면 작품 제목을 넣은 SVG **대체 표지**를 표시합니다. 원본 표지가 준비되면 실제 표지를 사용합니다. 대체 표지는 브라우저에서 만들며 원본 이미지 다운로드나 저장소 변경을 하지 않습니다.

저장된 목록이 30분 캐시 만료 시각을 넘었어도 먼저 표시하고 뒤에서 최신 목록을 조회합니다. 화면에는 저장 목록/갱신 중/갱신 실패 상태를 구분합니다. 갱신 실패와 원본 접근 대기 중에도 기존 목록을 지우지 않습니다. 최초 조회처럼 저장 목록 자체가 없으면 기존 40개 자리와 순차 표시를 사용합니다.

브라우저는 같은 검색 조건의 최근 세 페이지를 로그인 세션 안에서 보관합니다. 탭 복귀나 이전 페이지 이동에서 해당 목록을 먼저 표시하고 필요할 때 조회하며, 명시적 검색/새로고침과 데이터 변경은 갱신을 요청합니다. 로그아웃하면 목록·선택·카드 캐시를 폐기합니다.

페이지를 요청하면 먼저 40개 카드 자리를 표시하고, 서버에서 준비된 목록을 원본 순서대로 채웁니다. 캐시한 원본 페이지가 있으면 해당 구간부터 표시하며 나머지 구간을 기다립니다. 진행 중 자동 회차 조회는 대기합니다. 조회 오류가 나면 표시한 작품은 유지하고 미확인 구간을 건너뛰는 다음 페이지 이동을 막습니다. 화면을 떠나면 전송을 취소하고 돌아올 때 중단된 페이지를 다시 요청합니다.

목록은 **페이지당 40개**로 구성합니다. 원본 사이트가 더 많이 표시해도 초과 작품은 다음 대시보드 페이지로 이어집니다. 마지막 페이지와 회차 필터 적용 결과는 40개보다 적을 수 있습니다. 페이지 이동 뒤 첫 번째 작품 위치로 자동 스크롤하며 검색 조건과 체크한 작품을 유지합니다.

작품 카드의 연재 상태 옆에 원본 목록이 제공한 5점 만점 평점을 표시합니다. 평점이 없거나 유효하지 않으면 **평점 미확인**으로 표시하며 임의의 점수를 채우지 않습니다. 이전 캐시에 평점이 없으면 목록을 다시 검색해 최신 값을 가져올 수 있습니다. 장르와 같은 태그는 생략하고 나머지 고유 태그만 표시합니다.

작품 카드 또는 제목을 누르면 현재 목록 위에 작품 소개 팝업이 열립니다. 표지·작가·공급처·장르·태그·줄거리·연재 상태·확인된 회차 수를 표시합니다. 사이트가 제공하지 않은 정보는 미확인 또는 정보 없음으로 표시합니다.

팝업에서 **이 작품 수집 예약**, **선택에 담기**, **원본 소개 페이지**를 사용할 수 있습니다. ×·닫기·Esc로 닫으며 현재 목록 위치·검색 조건·선택은 그대로 유지합니다. 닫은 뒤 키보드 초점은 작품 카드로 돌아옵니다. 제목 링크는 키보드와 새 탭으로 열기에도 사용할 수 있습니다.

소개 조회는 일반 작품 페이지 한 번만 읽으며 회차 전체 스캔이나 본문 수집을 시작하지 않습니다. 저장된 소개는 30분간 재사용하고 같은 작품의 동시 요청은 하나로 합칩니다. 조회 중 화면 이동·숨김·로그아웃은 화면 반영과 추가 폴링을 중지합니다. 목록 갱신의 빈 작가/태그가 저장 소개를 지우지 않습니다.

팝업이 열려 있을 때 뒤쪽 목록의 자동 회차 확인은 보류합니다. 닫으면 기존 목록에서 확인을 재개합니다.

## 브라우저 연결 정기 갱신

서버 실행 중 12시간마다 오래된 브라우저 연결을 정리합니다. 수집 중인 슬롯은 현재 회차 저장이 끝난 뒤 다음 회차를 읽기 전에 같은 슬롯·프로필로 새 연결을 확보합니다. 직접 인증 중인 창은 사용이 끝난 뒤 갱신합니다. 작품 찾기의 공용 연결도 목록·소개 조회가 끝난 뒤 정리하며 다음 요청에서 다시 엽니다.

브라우저 프로필은 그대로 사용하고 사이트의 인증 대기·요청 제한·사용자 일시정지를 유지합니다. 이 기능은 브라우저 연결 갱신이며 사이트가 발급한 로그인 세션의 만료 시간을 연장하지 않습니다. 사이트 로그인 자체가 만료됐으면 정상 로그인 또는 직접 인증이 필요합니다.

관리자 상태 API의 `browserSessionRefresh`에서 12시간 간격·마지막 갱신·다음 갱신 시각·갱신 대기 슬롯을 확인할 수 있습니다. 상세 로그에는 `SESSION_REFRESH` 단계가 기록됩니다.

## 추출 프리셋

**프리셋 → 세 페이지 유형 → 추출 항목** 구조입니다. 소설 목록(`/novel`), 소설 정보·회차 목록(`/novel/{workId}`), 회차 본문(`/novel/{workId}/{episodeId}`)을 하나의 프리셋에 저장합니다. 정보 페이지의 소설 제목과 아래 회차 제목은 별도 항목입니다.

이미지 안내를 확인하고 북마크를 등록한 뒤 **원본 새 탭 열기**로 이동합니다. 원본 도구에서 항목 → 영역 클릭 → **이 항목 저장**으로 고정합니다. 같은 항목을 다시 고르면 고정 영역이 강조되고, **선택 항목 미리보기**는 해당 값만 보여줍니다. 모두 지정한 뒤 **프리셋 서버 저장**을 누르면 대시보드에서 검증·저장합니다. 로그인/저장 연결이 만료되면 새 북마크를 등록하거나 고급 JSON 가져오기를 사용합니다. 북마크바 표시는 Ctrl+Shift+B (Mac: ⌘+Shift+B)입니다.

원본 화면과 조작은 개인 브라우저에서 처리하며 서버 캡처를 사용하지 않습니다. 같은 브라우저 프로필의 기존 로그인 상태·북마크를 사용합니다. 웹앱이 북마크를 자동 등록하거나 새 창에서 자동 실행할 수는 없습니다. 새 창/탭 형태는 브라우저 설정에 따라 달라집니다. 저장·원본 검증·적용은 별도 동작이며, 웹툰 실행 연결은 아래 개발 구현 범위를 따릅니다. [상세 사용법](PRESETS.md)을 참조하세요.

## 개발 중인 웹툰 연결

작품 찾기의 **작품 유형**에서 소설·웹툰을 선택합니다. 웹툰은 연재 중(`/ing`)과 완결(`/end`) 목록, 제목·작가 검색을 구분합니다. 유형을 바꾸면 진행 중인 목록 요청과 선택을 정리하며 소설·웹툰의 캐시와 작품 ID가 섞이지 않습니다.

장르·플랫폼 항목은 원본이 제공한 필터를 사용합니다. 아이콘형 플랫폼 버튼은 실제 라벨로 표시하며, 검색어와 장르·플랫폼을 함께 선택하면 모든 원본 검색 페이지를 확인한 뒤 조건에 맞는 결과를 페이지로 나눕니다. 일반 목록은 최신·신작·북마크·조회·평점·화수 정렬을 제공합니다. 검색 결과는 원본이 제공하는 최신·북마크·조회·화수 정렬을 선택할 수 있습니다.

웹툰 소개 팝업 또는 선택한 작품 등록은 서버 수집 예약을 만들고 프리셋 사본·해시를 고정합니다. 이후 프리셋 편집은 이미 만든 예약을 바꾸지 않습니다. 소설·웹툰 합계 최대 두 작품을 동시에 수집합니다.

웹툰은 원본 브라우저가 받은 이미지 바이트를 DOM 순서대로 저장하며 같은 이미지가 반복돼도 위치를 유지합니다. 개별 이미지 8 MiB, 회차 512 MiB, 회차 최대 1,000장입니다. 실패·중단 회차는 부분 체크포인트로 남기고 저장 완료 회차로 계산하지 않습니다. 이어받기 때 이미지 목록·내용·설정 해시가 달라지면 충돌을 표시하며 덮어쓰기는 명시적으로 선택해야 합니다.

보관함의 **작품 유형**으로 소설·웹툰을 구분할 수 있습니다. 웹툰 **회차 열기**는 저장 이미지를 보여주며 **회차 CBZ 받기**, **작품 ZIP 받기**를 제공합니다. ZIP에는 해시 검증된 저장 회차의 CBZ만 들어갑니다. 저장하지 못한 회차를 포함한 전체 작품 완료로 표시하지 않습니다.
