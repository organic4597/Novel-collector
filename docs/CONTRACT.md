# 기능 계약

## 실행 진입점

Windows/Linux 공통 진입점은 `node run.mjs`입니다. 실행기는 프로젝트 자신의 경로를 기준으로 의존성·Python/OpenCV·Chromium을 준비하고 같은 `startServer`를 호출합니다. 기존 HOST/PORT/프로필/브라우저/Python 설정은 유지합니다. 서비스는 `--no-setup`으로 자동 설치를 금지하고 `--check`는 서버를 시작하지 않습니다. 모든 준비 명령은 셸 문자열이 아닌 실행 파일·인자 배열로 전달합니다.

## 북마크릿과 추출 프리셋

- 링크 입력은 사용자 브라우저의 새 창/탭에서 원본 HTTPS 페이지를 직접 엽니다. 서버 캡처·원격 브라우저·원본 열기 API를 사용하지 않습니다. 사용자 클릭 안에서 열기를 요청하며 다른 창에 opener를 노출하지 않습니다.
- 북마크릿의 최초 등록과 원본 창에서 실행은 사용자 동작입니다. 웹앱이 브라우저 북마크를 자동 등록하거나 다른 origin에서 자동 실행한 것으로 표시하지 않습니다. 유형·항목은 새 북마크의 초기 설정이며 이미 등록한 북마크를 자동으로 갱신하지 않습니다.
- 원본 HTTPS 페이지의 요소 선택·강조·미리보기는 사용자의 브라우저에서 처리합니다. 북마크릿은 실행 함수를 자체 포함하며 외부 스크립트 다운로드나 대시보드로의 자동 전송을 하지 않습니다.
- 유형과 지원 항목마다 합성 이미지에 선택할 위치를 표시합니다. 실제 원본 캡처를 안내 이미지에 저장하지 않습니다.
- 새 프리셋은 버전 2의 세 페이지 그룹입니다. 소설 정보와 회차 목록을 같은 detail 페이지로 묶으며 소설 제목/title과 회차 제목/chapterTitle을 분리합니다. 기존 버전 1 설정은 유지하고 UI에서 그룹으로 변환할 수 있습니다.
- 원본의 클릭은 후보 선택이며 항목 저장 전에는 고정하지 않습니다. 브라우저 저장 성공 후 고정으로 표시하고 재선택·재실행·스크롤 때 현재 항목의 저장 영역을 다시 강조합니다. 반복 영역 교체/삭제는 종속 선택자를 무효화합니다.
- 미리보기는 현재 항목에만 한정하며 다른 항목을 선택하면 지웁니다. 미리보기 값은 설정 export와 서버 저장에 포함하지 않습니다.
- 최종 서버 저장은 사용자 클릭으로 대시보드에 설정 fragment를 반환합니다. 대시보드가 발급한 24시간 저장 연결·origin·관리자 인증을 확인하고 fragment를 지운 뒤 기존 CRUD API로 저장합니다. 로그아웃은 저장 연결을 폐기합니다. 원본에서 직접 cross-origin API 요청을 허용하지 않습니다.
- 저장 JSON에는 유형·공개 origin·쿼리 없는 경로 패턴·선택자·Shadow DOM 경로·반복/상대 연결만 포함합니다. 미리보기 원문과 입력값은 내보내지 않습니다.
- 관리자 인증과 기존 요청 출처 검사를 통과한 CRUD API로 최대 100개 프리셋을 원자적으로 저장합니다. 설정은 최대 32KiB, 저장소는 최대 2MiB이며 실패한 쓰기는 활성 레코드를 바꾸지 않습니다.
- 목록 카드/목차 행에 연결된 상대 선택자와 접근 가능한 Shadow DOM을 지원합니다. 접근할 수 없는 closed root와 iframe 내부는 지원하지 않습니다.
- 화면 전환·로그아웃 후 늦은 응답은 편집 상태나 북마크 코드 입력란을 복원하지 않습니다. 재진입하면 저장 목록을 다시 읽고 편집 버튼을 사용할 수 있습니다.
- 현재 기능은 프리셋 제작·검증·관리·원본 미리보기입니다. 자동 수집 파서에 적용하거나 수집 원본·인증을 바꾸는 활성화 기능은 포함하지 않습니다. 사용법은 [프리셋 문서](PRESETS.md)를 참조하세요.

## 저장과 작업

- 최대 두 작업, 작품 내부 회차는 순차 처리합니다. 같은 작품의 동시 실행을 막습니다.
- Scheduler가 작업 상태와 일시정지·취소·재개를 소유합니다. 사용자 일시정지는 자동 인증 복구나 대기 만료보다 우선합니다.
- FolderStore가 본문, 작은 회차 메타데이터, 실패 기록과 내보내기를 원자적으로 저장합니다. 작업 기록 삭제와 보관 본문 삭제는 구분합니다.
- 캐시한 정상 회차는 재사용하며 실제 본문 요청만 요청 실패·대기 통계에 반영합니다.
- 일반 본문 오류·미업로드·준비중 회차는 실패 기록 후 다음 회차로 진행합니다. 연속 실패 횟수만으로 전체 대기를 시작하지 않습니다. 서버의 HTTP429·Retry-After 제한은 즉시 적용하고 수동 일시정지를 보존합니다.
- 예약 삭제는 Scheduler가 취소·작업 종료·lease 무효화 후 기록을 로컬 trash로 옮기는 순서를 소유합니다. 지연된 종료는 DELETE202로 안내하며 저장 본문·다른 슬롯은 유지합니다. 삭제 중 예약은 재개/재시도를 허용하지 않고, 재시작 때 미완료 삭제를 마무리합니다.
- 목차 로딩 시간 초과는 새 탐색으로 한 번 더 확인합니다. 다시 실패하면 누적/예상 회차 수와 더 보기 버튼 상태를 기록하며, 일부 목차를 전체로 저장하지 않습니다. 인증·요청 제한·취소는 이 재시도 대상이 아닙니다.

## 브라우저와 인증

- 슬롯별 Context/Page를 배타적으로 소유합니다. 사람 확인이 끝나면 같은 브라우저를 수집기에 인계합니다.
- 정상 본문 확인과 저장 checkpoint가 끝나야 해당 슬롯의 인증 대기를 해제합니다.
- 자동 로그인은 현재 세션의 정상 로그인/PIN 요청만 사용합니다. 계정은 사이트별로 암호화하며 다른 origin으로 복사하지 않습니다.
- 공개 API와 로그에 비밀번호, PIN, 쿠키, CAPTCHA 토큰, proof 원문을 노출하지 않습니다.

## 조건부 CAPTCHA

- 현재 회차 응답의 `error === 'captcha_required_daily_quota'`가 실행 기준입니다. 일반 응답은 분석이나 입력을 시작하지 않습니다.
- 세션별 한 번의 진행 작업을 공유하고 호출자별 요청 ID를 보존합니다.
- 원본 뷰어의 본문 없는 발급 요청을 채택합니다. 챌린지 ID·이미지·크기·y·수신 시각을 한 객체로 취급합니다.
- 명확한 후보에 대해서만 실제 브라우저 입력을 수행합니다. trail 시간 범위는 1800..4500ms, 기본 목표는 2400ms입니다.
- 같은 챌린지는 한 번만 검증합니다. 재시도 가능한 실패는 현재 회차의 새 요청과 새 챌린지로 최대 5회 시도하고, 다섯 번째 실패에서 기존 수동 CAPTCHA 확인으로 전환합니다. 자동 예산이 남아 있으면 수동 UI를 표시하지 않습니다. 작업 취소·세션 변경·요청 제한은 즉시 중단합니다.
- 엄격한 성공 응답을 기존 처리기에 전달하고, 콘텐츠 요청의 nonce/proof 갱신은 기존 처리기가 맡습니다. 타임아웃 뒤 늦은 토큰은 전달하지 않으며 이전 답안이나 proof를 재전송하지 않습니다.
- 자동 재시도 버튼은 같은 소유 세션에서 새 5회 예산을 시작합니다. 진행 중 중복 실행과 수동 입력을 차단하며, 성공 시 실제 본문을 저장한 뒤 필수 슬롯을 확인해 재개합니다.
- 단계별 ETA는 현재 확인 시간을 반영합니다. 인증 재시도는 목차를 다시 읽지 않으며, 재개 시 완전성이 검증된 저장 목차를 재사용합니다.
- 상세 로그는 관리자 인증·bounded cursor·메모리 상한·로컬 파일 순환을 사용합니다. 인증값·본문·원시 응답을 저장하지 않습니다.

상세 인터페이스, 오류 코드와 평가 방법은 [CAPTCHA 문서](CAPTCHA.md)를 참조하세요.

## 작품 소개 조회

`GET /api/discover/:id/overview`는 저장 정보와 조회 상태만 읽습니다. `POST`의 빈 객체 요청은 일반 작품 소개 페이지 한 번의 백그라운드 조회를 시작하며 대기 중이면 202로 반환합니다. 관리자 인증과 요청 출처 검사를 사용합니다. 전체 목차·본문·로그인·CAPTCHA 입력은 이 작업에 포함하지 않습니다.

작가·태그·장르·줄거리·연재 상태·표지는 기존 메타데이터 파서를 사용합니다. 소개는 30분 캐시와 작품별 중복 억제를 적용하고, 목록의 빈 값으로 풍부한 저장 정보를 덮어쓰지 않습니다. 소개는 모달 팝업으로 표시하며 목록 화면·필터·선택·스크롤 위치를 유지합니다. 닫힌 뒤의 응답은 렌더링하지 않고 초점을 원래 카드로 복원합니다. 팝업이 열린 동안 뒤쪽 목록의 자동 회차 확인을 보류합니다.
